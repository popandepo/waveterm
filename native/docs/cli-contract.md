## 0. Principles (each one removes a defect listed in the appendix)
1. One output form: JSON on stdout for success, JSON on stderr for failure. An empty list is `[]`. No telemetry call. Callers must keep the two streams apart (never `2>&1` into a JSON parser).
2. One id grammar: a full lower-case uuid, or the keyword `this` (the caller's block) or `tab` (the caller's tab), accepted wherever an id of that type is expected. No 8-char prefixes, no numbers, no view names, no `type:` prefixes. The verb says what type it wants.
3. Authority comes from the app's record of the calling block, never from an environment value: `this` and `tab` are read from the record, not from WAVE_BLOCK.
4. The app enforces the rules, not the scripts: scope (workspace), ownership, capability (focus, admin), safety (running programs, own tab). The scripts keep their own extra rules (idle probe, never-list) but nothing depends on a well-behaved script. The threat model is stated in section 1: it stops mistakes and prompt-injected sessions, not hostile code of the same Windows user.
5. No verb moves the shown tab or what a stack shows unless it is a focus verb AND the caller holds `focus` (3.4). Creating verbs add things in the background by default; `--focus` is the exception. No verb ever takes keyboard focus from a tile the owner is typing in (D6).
6. A change is applied before the call returns, and the answer says what was applied. No "queued".
7. One text-safety rule for output and one for input (section 7).
8. Several keys or steps in one call are one change: all or nothing, except the creating verbs (exit 7).
9. Target convention: the main object of a verb is positional (a block, or a tab); secondary objects are flags (`--to`, `--from`, `--stack`, `--tab`). `--block` / `--tab` flags exist only where the object may be left out and then means the caller's own (`attention`, `badge`, `tab style`, `run`, `web open`). `tab rename` and `session close` need an explicit TAB (the keyword `tab` is accepted).

## 1. Transport, identity, threat model, exit codes
- Binary: `wave.exe` (a thin client). It reads the block token from env, sends one request `{verb, args, token}` over the named pipe `\\.\pipe\wave-<instance>`
  on a fresh connection, prints the app's reply, exits. The request format is internal and may change with the app.
- Environment given to a program the app starts in a block (and nothing else of ours): `WAVE_TOKEN` (opaque, per block, rotated each app start; replaces WAVETERM_JWT
  and the swap token), `WAVE_PIPE`, `WAVE_BLOCK`, `WAVE_TAB`, `WAVE_WORKSPACE` (information for scripts, ignored as identity), `WAVE_BIN` (folder with wave.exe, put on PATH by the app; the app promises no fixed root for it, so a script must not compare it to one).
  The app also sets `TERM_PROGRAM=wave`; no variable named WAVETERM exists any more. `WAVE_CONN` and `WAVE_VERSION` are dropped (no caller in the two script trees reads them; Tether/Atlas were not searched: gate 3 greps them first). The app starts the program directly with this
  environment: no swap-token exchange, no `token` verb. D1 is decided here: the names are renamed and every reader changes (section 5).
- A wave.exe outside a block has no token: every verb fails with exit 3; scripts keep their own early check (exit 2 today) on WAVE_TOKEN.
- Threat model, stated plainly. Every session and the owner run as the same Windows user, and a session runs arbitrary code through its tools. The design stops
  MISTAKES and PROMPT-INJECTED sessions that only use the CLI (and ordinary tools): a session cannot type into, close, delete, retitle or move the manager, nor get focus
  rights, by calling `wave`. It does NOT stop a hostile process of the same user that attacks the app or another process directly (OpenProcess + thread injection into
  the manager's process, reading its memory or environment, DuplicateHandle of the job). A real boundary against that needs a separate Windows account for sessions, or a
  per-process secret handed through a handle the app creates; neither is designed here (D10). The controls below are what the CLI path gets:
  the token is bound to the block's record; each block's whole process tree runs in one Windows Job Object owned by the app; a request is accepted only when the token
  matches AND the process on the pipe (GetNamedPipeClientProcessId, read for that one connection) is a member of that block's job (IsProcessInJob). A stolen token used from
  a process outside the block's job is refused (exit 3). Orphans stay in the job, so a helper that outlives its parent program keeps working until the block is deleted, which
  kills the job. The token is revoked when its block is deleted or its job is empty. The app never writes a token to a file and never logs a token, argv, `--env` or meta value.
- Two words, one meaning each. ALIVE: the block's main program has not exited (status `init` or `running`); this is what every `running` field says and what `send` needs. UNFINISHED: a terminal block whose status is not `done` (alive, or not known to have ended: `none` after an app restart); this is what the safety rules of 3.3 use, and every listing carries an `unfinished` field so a script can decide about `--force` without guessing. Helpers still alive in the job count for neither; deleting a block kills everything still in its job.
- Exit codes (stable, repeated in the stderr JSON): 0 ok; 1 internal error; 2 usage (a bad flag, value or id: nothing was changed); 3 denied (no token, missing capability, not the owner of a
  block the caller can see); 4 not found (an id that does not exist OR that the caller may not reach: the two are indistinguishable, same message); 5 refused by a safety rule (running
  program, own tab, invalid state such as "not in a group"); 6 app not reachable; 7 partial success (only `session start`, `run`, `web open`: something was created and a later step failed; stdout
  carries the ids with `"status":"partial"` and a `"warning"`, stderr carries the error object).
- stderr on failure: `{"error":{"code":<exit code>,"kind":"<denied|notfound|refused|usage|partial|internal|unreachable>","message":"<safe text>","reason"?:"<word>"}}`. Messages never contain a secret. `reason` is present when a script may want to tell causes apart without reading the message; the words are stable: `notoken` (client, no WAVE_TOKEN), `badtoken`, `capability`, `notowner`, `unfinished`, `owntab`, `lasttab`, `duplicate`, `restart`, `nomatch`, `notweb`, `notterm`, `notrunning`, `notingroup`, `samegroup`, `othertab`. Other refusals carry none. Scripts branch on the exit code first and on `reason` only inside one exit code.

## 2. Object model the verbs see
workspace > tabs (ordered) > blocks. A tab shows its blocks as tiles; a stack (group) is one tile with several member blocks, one shown.
Views in use: `term` (a program in a pty), `web`. No other view exists in the native app (his layout, by view; recount with `block list` grouped by `view`: C:\Projects\Personal\MalfestioMaster\reports\wave-native-his-layout.md, counted by the manager from the block list).
Every block and every tab records `createdby` (the block whose token made it; none when the app or the owner made it). Block meta is a small typed map with a fixed key set (section 6).

## 3. Rules that apply to every verb
### 3.1 Scope
A token reaches blocks and tabs of its own workspace. Cross-workspace access needs the `crossworkspace` capability. An id outside the caller's reach behaves exactly like an unknown id (exit 4, same message).
### 3.2 Four classes of verbs
- LIST (`session list`, `block list`, `meta get`, `whoami`): any token, own workspace. They show names, status, tab order, `session:*` meta and (for blocks the caller owns or created, or with `admin`) `cmd`/`cmd:args`/`cmd:cwd`; where those are left out the element carries `"hidden":["cmd","cmd:args","cmd:cwd"]` so a reader can tell "not allowed" from "absent". Never `cmd:env`; `url` redacted (4.5). `session:id` is visible to every token (it is not a secret; the starter resumes by it).
- READ CONTENT (`screen`, `block shot`, `web text`): the caller's own block, blocks it created, or any block with `admin`. Otherwise exit 4 with "that block is not available to this caller" (the same answer for all three verbs and for a block that does not exist). Another session's screen can hold pasted credentials; a normal session does not read it.
- CREATE (`session start`, `run`, `web open`, `tab new`): any token, own workspace. The new block records `createdby`. A creator may give a new block only capabilities it holds itself (3.4). A session may add a HIDDEN MEMBER to any stack of its workspace (this is how it shows him a page), but a new stack member is NEVER made the shown member and never takes focus without `focus` (principle 5): a session cannot cover the manager's terminal with a page. A new TOP-LEVEL TILE (`run` or `web open` without `--stack`, `group remove`) changes what a tab looks like for everyone in it, so it needs a tab the caller owns (below) or `admin`; otherwise exit 3. Tab names are unique in a workspace and `session:name` is unique in a workspace (case-insensitive): a duplicate is exit 5 (scripts find a tab by name and close a session by name; a session must not be able to make those ambiguous).
- ACT ON AN EXISTING BLOCK OR TAB (`send`, `block delete`, `session close`, `meta set`, `meta unset`, `attention` and `badge` on another block, `group add|remove|move` involving a block the caller did not create, `tab rename|move|style`, `workspace style`): allowed for the caller's own block, for blocks it created (the `createdby` chain), and for any block with `admin`. Otherwise exit 3. `session close TAB` checks every block in the tab, not only the tab: a block of another session in a tab the caller created is not the caller's to kill; it is all or nothing (the exit 5 text names the first unfinished block). A TAB is owned by its creator chain or by `admin`; sitting in a tab grants nothing over it (the area tabs are made by the owner or the app, so no session can rename, restyle, move or close them; `tab style` with no `--tab` from a stacked session is exit 3). `workspace style` is `admin` only. `group move` moves ALL members of the source stack and needs ownership of every one of them; when a stack loses its shown member the FIRST member (the original tile) becomes shown again, never a hidden page someone else added. If an ancestor in a `createdby` chain was deleted, the chain stops there: the orphaned child is unowned (admin only); authority never passes up.
- FOCUS (`tab switch`, `group activate`, any `--focus`, `--activate`): needs `focus`. Exit 3 otherwise.
### 3.3 Safety
- `block delete` and `session close` refuse a block or tab whose program is not known to be finished (exit 5) unless `--force`. "Unknown status" counts as running. The refusal is decided by the app, not by a flag the client sets.
- `session close` refuses the caller's own tab (exit 5) even with `--force`. A block deleting itself is deleting a running block like any other: it needs `--force` and ends its own program.
- Closing the last tab of the window is refused (exit 5); the window is never closed by a CLI call.
### 3.4 Capabilities
Fields of the app's block record, fixed when the block is made, never writable by `meta set`, never read from meta: `focus` (move the shown tab or a stack's shown member; `--focus`), `admin` (act on blocks it did not create, read other blocks' content),
`crossworkspace`, `grant` (give capabilities at creation with `--cap`). A normal session has none. They are given only (a) by the app to the block it starts from its own config (the `manager` entry of the app's config file, which no CLI verb writes), or (b) at creation by a token that
holds `grant`, with `--cap focus|admin|crossworkspace` (repeatable), limited to what the creator holds. `grant` itself is never passed on: only the config entry has it. A block started with `--restart` keeps its record, so rights survive an app restart; `session:id` and every other meta key prove nothing.
A promotion by the owner in the UI ("make this block the manager") clears `createdby`, so no session owns the manager block through a creator chain. `focus` covers showing (tab switch, stack member, the focused tile of a tab); no verb takes keyboard input away from a tile the owner is typing in (D6). The manager block has `focus`, `admin`, `grant`. `wave whoami` (4.14) lets a script ask its own rights instead of guessing.

### 3.5 The `manager` entry of the app's config file (decision D3, designed here)
The config file is JSON, owned by the owner, read at launch; no CLI verb writes it. One optional `manager` object:
`{"manager":{"name":"manager","tab":"Home","cwd":"C:\\Projects\\Personal\\MalfestioMaster","argv":["pwsh","-NoLogo","-File","C:\\...\\Start-ResumableSession.ps1","-SessionId","<uuid>","-Name","manager","-ConfigDir","C:\\\\...\\\\config"],"env":{"CLAUDE_CONFIG_DIR":"C:\\\\...\\\\config"},"caps":["focus","admin","grant"],"session":{"name":"manager","id":"<uuid>"}}}`.
Rules (each a test in section 11): only these keys (an unknown key is a config error); `cwd` absolute and existing; `argv` a non-empty array of strings with a non-empty first element; `env` valid names (it is the only extra environment the program gets: its environment is the app process's own environment block, which the launcher has already stripped of CLAUDE* and STATUS_* variables, plus the WAVE_* variables of section 1, plus this `env`; nothing from any caller); an optional `tabs` array of area tab names that the app creates at launch when missing, so that no session can squat them; `caps` a subset of focus, admin, crossworkspace, grant, no duplicates (default focus, admin, grant); `session` keys become `session:KEY` with the rules of 4.1; `tab` is the name of a tab (made when missing) and `name` the block title. The app starts this block at every launch in that tab with restart-at-start (the inline-shell refusal of 4.1 does not apply: the owner wrote it), `createdby` none, and the listed capabilities in its record. A config error stops that block from starting and is shown to the owner; it never falls back to rights from anywhere else. The block keeps its rights across restarts (they are in the record, not in meta). The one-time move of the already running manager into this entry is the manager's own manual step.

## 4. Verbs (the keep list). Callers that exist today are marked with the file:line they are updated in.

### 4.1 session start
`wave session start [--name N] [--cwd ABS] [--args-file F | -- CMD ARGS...] [--color C] [--symbol S] [--stack BLOCK] [--activate] [--restart] [--meta session:KEY=VALUE]... [--env K=V]... [--cap focus|admin|crossworkspace]...`
- `--cwd` must be absolute and exist (exit 2). Default: the calling block's cwd.
- `--args-file`: UTF-8 JSON array of strings, BOM tolerated (a PowerShell 5.1 BOM breaks the Go parser today). With `--` command too: exit 2.
- `--name`: at most 60 UTF-16 units, no characters the `Refuse` predicate names. Empty: the app names the tab `T<n>`.
- `--color` CSS name or #RRGGBB[AA]; `--symbol` an icon name (`[a-z0-9-]{1,40}`; the old `solid@ regular@ brands@ custom@` prefixes are dropped) or at most 2 graphemes / 32 bytes without `<>&"'` backtick backslash. Same rules as `tab style`.
- `--stack BLOCK`: no new tab; the block joins the stack of BLOCK (same workspace), not shown unless `--activate`. `--name/--color/--symbol` then go on the block (title, icon colour, icon); without `--stack` they go on the tab. `--activate` is a FOCUS verb: it needs `focus`.
- `--restart`: the app starts the same command again at every app start, output kept (the three cmd flags are set to true/false/false). Refused (exit 5) when the argv contains `--session-id`, or when the command is a shell or interpreter run with an inline-code flag (the list of wshcmd-session.go:171-187, text matching, best effort). The `manager` entry of the app config is not subject to this check (the owner wrote it).
- `--meta`: only `session:KEY`, KEY `[A-Za-z0-9._-]+`, values strings without `Refuse` characters, at most 200 code points, no key twice.
- `--env`: KEY=VALUE, empty key refused, a repeated key is exit 2. The program gets ONLY these plus section 1's variables and the app's own process environment (the Windows user's variables as the launcher started the app), never the caller's environment.
- `--cap`: needs `grant`; else exit 3. Neither `--args-file` nor `--` (no command) is exit 2; `--cwd` defaults to the caller block's cwd.
- Order: every check (usage 2, scope 4, rights 3, restart 5, uniqueness 5) happens BEFORE anything is created, so a refused call leaves nothing behind and a caller without `grant` or `focus` gets exit 3, never exit 7.
- Effects, in this order: create tab (not shown), set tab style, create the block (the program starts even when the tab is never shown), `--activate`. A failure before the block exists leaves nothing behind. A failure after returns exit 7 with the ids.
- stdout: `{"tabid","blockid","status":"ok"}`, with `--stack` also `"stackedwith"`; with `--stack`, `tabid` is the EXISTING tab that holds the stack, never a new one (so exit-7 cleanup in stack mode is `block delete BLOCK --force`, and closing that tab would close the host).
- Callers: Open-WaveSession.ps1:133-156 (flags unchanged), Restore-Sessions.ps1:100-119 only if D5 keeps it.

### 4.2 session list
`wave session list [--all]` (`--all` needs `crossworkspace`). Own workspace by default. stdout: array in tab-bar order, `[]` when empty:
`{"tabid","name","workspaceid","index":<0-based>,"active":<bool>,"color"?,"symbol"?,"running":<bool>,"unfinished":<bool>,"blocks":[{"blockid","view","title"?,"status":"none|init|running|done","exitcode":<int>,"unfinished":<bool>,"meta":{every session:* key of the block}}]}`.
`running` = a terminal block is alive; `unfinished` = a terminal block is not known to have ended (section 1): a script that decides whether `session close` needs `--force` reads `unfinished`, not `running`. New fields: `index`, `active` (replaces `api list --json` `activetabid`), `blocks[].meta` (replaces `blocks list --json` for `session:name`). `running` is true when any term block is `init` or `running`; `none` = no program started in this app run. A script that shows "ended" or decides about `--force` reads `unfinished` (or `blocks[].status == "done"`), never `running == false`: a block with status `none` has `running:false` and is still unfinished.
Callers: Wave-Sessions.ps1:127 and :130 (the `api list` call is deleted), HomeTab.Lib.ps1:13, Set-HomeTile.ps1, Show-InWave.ps1, Check-HomeTile.ps1.

### 4.3 session close
`wave session close TAB [--force]` -> `{"closed":"<tabid>","blocks":<n>}`. Rules 3.2 (ownership per block) and 3.3. Exit 5 text names the first unfinished block. Caller: Wave-Sessions.ps1:300-302 (it keeps its own "never own tab" check).

### 4.4 tab and workspace
- `wave tab new [--name N] [--activate]` -> `{"tabid","status":"ok"}`, no blocks in it. `--activate` is a FOCUS verb. (Today `CreateTab` may add a default block even with "empty": appendix part A quirk 15; D7.)
- `wave tab rename TAB NAME` -> `{"tabid","name"}`, `wave tab move TAB --index N` -> `{"tabid","index"}`, workspace style -> `{"workspaceid","accent"?}`; (the app moves; today's server overwrites the id list and can drop a tab), `wave tab style [--tab TAB] [--color C] [--accent C] [--symbol S] [--clear]` (keys `tab:flagcolor`, `tab:accent`, `tab:symbol`; colour names stored lower-case; `--clear` with another flag is exit 2). Stdout of `tab style` is `{"tabid","color"?,"accent"?,"symbol"?}`.
- `wave tab switch TAB` -> `{"active":"<tabid>"}`. A FOCUS verb. Never raises an OS window and never moves keyboard focus (D6). Replaces `api goto --tab` (Wave-Sessions.ps1:270); `--window` and `--block` are cut.
- `wave workspace style [--accent C | --clear]` for the caller's own workspace; needs `admin` (it recolours the whole window). No `--workspace` id.
- `tab list` is cut: `session list` is the one listing. No caller needs `tab style`, `workspace style`, `tab rename`, `tab move` today; kept per the manager (attention ledger 20261015-C-8a0e4044, "tab create from the CLI").

### 4.5 block list
`wave block list [--tab TAB] [--view term|web] [--url URL] [--all]` -> array, `[]` when empty, tab order then layout order:
`{"blockid","workspaceid","tabid","view","stack"?:"<stackid>","meta":{...},"hidden"?:["cmd","cmd:args","cmd:cwd"]}`. `meta` carries the readable keys of section 6 except `cmd:env` (never) and `cmd`/`cmd:args` (only for blocks the caller owns or created, or with `admin`).
`url` is printed without user info, query and fragment (the home tile's entry token lives in the query and today lands in every listing and log). `--url URL` is the equality test the callers need
(Show-InWave.ps1:69 compares `meta.url -eq $url` today): both addresses are reduced the same way (scheme and host lower-case, default port dropped, empty path = `/`; the path, query and fragment are KEPT, so `?a=1` and `?a=2` are different pages) and the blocks whose stored url equals the given one are returned. No hash is exposed. Residual risk, stated (D13): `--url` is an equality test any LIST token can run, so a guessed query token can be tested; the Home entry token is 32 hex and single-use, and the owner accepts this for now.
Rule for starters: no secret goes into an argv or onto a command line (the prompt goes in a file, as today; the home entry token goes through `meta set --json-file -`, 4.7). `cmd`, `cmd:args` and `cmd:cwd` are readable only for blocks the caller owns or created, or with `admin`, because they show config folders and prompt-file paths of other sessions; `session:id` stays visible to every token (3.2).
Callers: Health-Check.ps1:324 (needs admin; scheduled outside a block it SKIPs as today), HomeTab.Lib.ps1:16 and Show-InWave.ps1:40, Wave-Sessions.ps1:242, Set-HomeTile.ps1. One change for them all: the verb name; JSON is the only form.

### 4.6 block delete
`wave block delete BLOCK [--force]` -> `{"deleted":"<blockid>"}`. The id is required (today a bare `deleteblock` deletes the calling block). Rules 3.2 and 3.3.
Callers: Wave-Sessions.ps1:250 (`--force`, the manager has admin).

### 4.7 meta
- `wave meta get [BLOCK] [KEY]...` (the one verb whose object is an optional positional: a first argument that is `this` or a full id is the block, anything else is a key of the caller's own block) -> object of the asked keys (all readable keys when none); a missing key is absent; own block returns `url` in full, any other block redacted as in 4.5. No caller today.
- `wave meta set BLOCK KEY=VALUE...` stores STRING values. `wave meta set BLOCK --json '{"key":"value",...}'` stores strings or null (= delete). `--json-file PATH` (or `-` for stdin) reads the same object from a file or stdin, so a value never has to travel on a command line (PowerShell mangles embedded quotes in native arguments, and an argv is visible to other tools); `--json` and `--json-file` together are exit 2. Both: all keys or none; keys must be the settable ones of section 6, else exit 2 and nothing changes. An empty value is a valid empty string; `meta unset BLOCK KEY...` deletes. No `/` nesting, no number or hex coercion, no `prefix:*` pseudo keys, no silently skipped keys. BLOCK is a block id or `this`. Rule 3.2 applies (a block the caller did not create needs `admin`). `session:name` must stay unique in the workspace (exit 5, case-insensitive, the empty value exempt); `session:id` has no rule. Stdout `{"id","set":[keys],"unset":[keys]}`.
- The `cmd:*` keys, `web:partition`, `view`, attention keys and tab/workspace keys are not settable here (section 6).
- Callers: Show-InWave.ps1:80 is replaced by `web open --title` (no later `meta set`, so a caller never needs rights over a block it reused); Set-HomeTile.ps1:76,91-93 (title and url on the Home tile, which the caller did not create: the manager runs it, or D2b) becomes one `--json-file -` call with the object on stdin (the url carries the home entry token: it must not be in an argv); Rehome-Manager.ps1 is deleted (section 5).

### 4.8 run
`wave run [--tab TAB] [--stack BLOCK] [--cwd ABS] [--env K=V]... [--restart] [--meta session:KEY=VALUE]... [--cap NAME]... [--title T] [--focus] -- CMD ARGS...` -> `{"tabid","blockid","status"}`.
`--restart`, `--meta`, `--cap` as in `session start`; `--title` sets `frame:title` (same rules as `--name`); `--focus` is a FOCUS verb. The command is the argv after `--` only; the program gets the app's own process environment plus section 1's variables and `--env`, never the caller's.
`--tab` omitted means the caller's own tab (`tab`); a full tab id works in any workspace the token may reach. No other flags (cut: `-m -x -X --delay -p -a -c --size`). A new block in a stack is not made the shown member without `focus`.
No script calls it once Rehome-Manager.ps1 goes (section 5); kept because `run` is the direct way to start one more program in a given tab (Boot.ps1:68 text).

### 4.9 group (stacks)
`wave group add BLOCK --to BLOCK` -> `{"stack","members":[...]}`; `wave group remove BLOCK` -> `{"unstacked"}`; `wave group move --from BLOCK --to BLOCK` -> members; `wave group activate BLOCK` -> `{"active"}` (FOCUS verb: it changes what the stack shows).
`group move` moves all members of FROM's stack to the end of TO's stack (or makes one) and needs ownership of every member (3.2); `group remove` adds a top-level tile and so needs an owned tab or `admin`; when a stack loses its shown member the FIRST member (the original tile) becomes shown again, never a hidden page someone else added. Same tab only (exit 5 otherwise). Applied before returning, exit 5 when the change is not valid ("not in a group", "already in the same group"), without today's 100 ms lag. `--focus` on add/remove/move needs `focus`.
Without `focus`, `add` places the block as a hidden member and leaves the shown member alone. Rule 3.2: `add`/`remove`/`move` of a block the caller did not create needs `admin`.
Callers: Show-InWave.ps1:101 (`group activate`, manager only), Restore-Sessions.ps1:124 only if D5 keeps it.

### 4.10 web
- `wave web open URL [--tab TAB] [--stack BLOCK] [--title T] [--focus]` -> `{"tabid","blockid","status"}`. URL `http:`, `https:` or `file:` only (exit 2 otherwise; no silent web search). The tile gets its own partition (`persist:<blockid>`) so `web text` can read it. `--title` sets `frame:title` at creation, so no later `meta set` is needed. Stack and tab rules as `run`; not made the shown member without `focus`. With `--stack` the tab is the stack target's tab and `--tab`, when given, must agree (exit 5); `session start --stack` also returns the stack's tab id.
  Caller: Show-InWave.ps1:73 (`--stack B --tab T --title T`; the before/after listing diff that found the new block id is deleted; the "already open" reuse test is `block list --view web --url U`; on reuse the script changes nothing on the block).
- `wave web text BLOCK [--selector CSS] [--max-bytes N]` -> `{"text":"<safe text>","truncated":<bool>}`. Selector at most 512 characters without control characters, matched by the app as a CSS selector (never spliced into code). `--max-bytes` 1..262144 (default the cap; counts bytes of the escaped text). READ CONTENT class: own, created, or `admin`; the only denial is exit 4 "that block is not available to this caller" (3.2). Reads only; no navigation, no focus.

## 7. Text safety (two rules)
Output: `Unsafe(r)` = Unicode category Cc, Cf, Zl, Zp, U+FFFD, a variation selector, or Other_Default_Ignorable_Code_Point. Any text the app prints that came from a page, a program or another session (web text, screen lines, titles, urls, error messages built from such text) has every unsafe rune replaced by `<U+XXXX>` (upper-case hex, at least 4 digits); `\n` and `\t` pass in `web text` and `screen`. JSON string escaping applies on top.
Input: `Refuse(r)` = Cc, Zl, Zp, bidi controls (U+202A-202E, U+2066-2069), and Cf except U+200D (zero width joiner) and U+FE0E/U+FE0F (variation selectors) inside an emoji sequence, so that `send` can type an emoji and a symbol can be one. Refused input is exit 2 (names, reasons, symbols, titles, `send` text without `--raw`).
The two predicates differ on purpose: what the app prints must be stricter than what it accepts. They replace several different predicates and escape formats (`<U+XXXX>`, `\xNN`/`\uNNNN`, `?`) of today.

## 12. Clarifications found by writing the executable tests (v0.3.1)
These were undefined or contradictory in v0.3 and are now fixed here; the stub and its tests follow them.
- READ CONTENT verbs (`screen`, `block shot`, `web text`) answer an unknown id, an unreachable id and a denied block with ONE message, "that block is not available to this caller", exit 4 (so existence does not leak). Section 4.10's "that web tile ..." wording is replaced by this one.
- Order of checks for `session close`: usage 2, scope 4, caller's own tab 5, last tab 5, tab ownership 3, block ownership 3, running program 5.
- Tab names are unique case-insensitively (as `session:name`). A tab or block id that is not a full lower-case id (or the keywords `this`, `tab`) is exit 2; an unknown or unreachable id is exit 4.
- `--cap` with an unknown name is exit 2; with `grant` (a real capability that cannot be passed on) exit 3. `tab move --index` out of range and an empty `tab rename` name are exit 2.
- Empty values: `frame:title` and `session:*` may be the empty string; `frame:icon`, `icon:color`, `frame:bordercolor` have no empty form (exit 2, use `meta unset`); `url` cannot be set to null or unset (exit 2). Colours are stored lower-case.
- Validation sees the value as given: a control character is refused even where trimming would remove it (`"A\n"` as a symbol is exit 2, not "A").
- `meta get` with no keys carries `"hidden"` like a list element when `cmd` fields are left out; with explicit keys a hidden key is simply absent. A `--json` object with a repeated key is exit 2.
- `send` key bytes (xterm): enter and return CR, escape and esc ESC, tab HT, backtab ESC [ Z, backspace DEL (0x7F), delete ESC [ 3 ~, insert ESC [ 2 ~, space, up/down/right/left ESC [ A/B/C/D, home ESC [ H, end ESC [ F, pageup ESC [ 5 ~, pagedown ESC [ 6 ~, f1..f4 ESC O P/Q/R/S, f5..f12 ESC [ 15,17,18,19,20,21,23,24 ~, ctrl+a..z bytes 1..26, alt+letter ESC then the letter. Empty tokens are skipped; all tokens empty is exit 2.
- `screen`: `total` is the number of lines after trailing blank lines are removed and before `--last` or `--max-bytes` cut; `truncated` is true when either cut dropped a line; `--max-bytes` is at least 1 (else exit 2); an empty screen answers `[]`. `web text` with a selector that matches nothing is exit 5.
- `attention clear` with one `--only-if-*` flag compares only that flag; a reason is trimmed and the 120-code-point limit applies after trimming. `badge --priority` is a number (the client passes it as given text; a non-number is exit 2).
- `run --stack` and `web open --stack` also return `stackedwith`. `--focus` on a new top-level tile (owned tab) asks that the new tile be shown and marked focused in its tab; it needs `focus`, never switches the shown tab and never takes keyboard input away from a tile the owner is typing in (D6). The stub does not model it.
- `redact` and equality: user info is dropped before comparing urls (`http://u:p@h/` equals `http://h/`); a url must start with `http://`, `https://` or `file:` (a drive path or a `//host/` path is exit 2).
- Manager config: `caps: []` means no capabilities; `name` and `tab` cannot be empty; a wrong-typed container (`caps`, `env`, `session`) is a config error and never falls back to the default capabilities; an env key with `=` in it is a config error.
- (v0.3.2) Unfinished programs: for a terminal block the safety refusal of 3.3 applies unless its status is `done`; status `none` (no program started in this app run) and `init` count as unfinished (a web block never needs `--force`). `send` still needs a running terminal.
- (v0.3.2) `cmd:runonstart` in listings reports whether the block was started with `--restart` (true) or not (false); it is no longer always true.
